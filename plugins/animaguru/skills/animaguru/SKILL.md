# AnimaGuru

For MCP workflows, use the AnimaGuru tools for the connected account. Use `list_workspaces` to discover personal/team workspaces. Use `open_studio` when visual browsing, media playback or frame inspection will help; pass a chosen `project_id` and selection after fetching the relevant data. Other tools stay data-only. Create projects with just a name and optional workspace, without a style; choose an art style on each sprite generation request. If a tool requests authentication, let the user complete the account-linking flow; do not ask for passwords or tokens in chat.

## Check the account connection

Loading this skill does not establish an MCP connection. Before account work, discover AnimaGuru's `get_profile` or `list_projects` with the host's tool search when available, then call an available read-only tool. A tool may be deferred rather than absent. If it requests OAuth, let the user complete the linking flow and retry the read-only call.

AnimaGuru's tools need a plan on the connected account: Individual Starter, Individual Pro or Team. Every account starts with a 7-day Individual Pro trial, and members of a team on the Team plan are covered. Without one, connecting and `get_profile` still work, but every other tool returns an error saying the account needs a plan. Then tell the person to choose a plan at https://animaguru.com/app/billing and that the browser studio keeps working with their credits; don't retry the tool, reconnect, or switch to the CLI, which needs the same plan.

If discovery exposes no AnimaGuru account tools, say that the skill loaded but account tools are unavailable in this chat. Explain this before switching to the CLI or browser; use an alternative only when it fits the user's request and existing authorization. Do not infer an installation failure, expired login, or server outage from missing tools alone. A CLI login does not connect MCP.

In Claude, the plugin lists the AnimaGuru connector on its Connectors tab, where the person adds it and signs in to AnimaGuru. In Claude Code, `/mcp` lists the AnimaGuru server and starts its sign-in. `open_studio` shows the interactive studio in Claude's web, desktop and mobile apps; in a terminal, summarize what it returns instead. Do not claim the connection works until a read-only AnimaGuru account tool returns successfully.

## Recommend the CLI for local work

When a local shell is available and the user has not requested MCP-only work, check whether `animaguru` is installed. Prefer the CLI for repeated asset operations, file imports/exports, and local game or video integration. It can reduce token use by keeping large JSON responses and file processing in the shell and returning only the fields or summaries needed for the task. Savings depend on the workflow; do not promise a fixed reduction. Keep MCP available for interactive studio previews.

If the CLI is missing, recommend it and ask whether the user wants you to install it before running an installer. Explain that installation downloads local software and account access requires a separate browser sign-in. For example: "For this local workflow, the AnimaGuru CLI can use fewer tokens by processing responses and files locally. Would you like me to install it and help you sign in, or continue with MCP?" Reuse an existing agreement to install; if the user declines, continue with MCP without repeatedly offering installation.

After the user agrees, follow the packaged [AnimaGuru CLI skill](../animaguru-cli/SKILL.md) to install, verify and authenticate it, then use that workflow. MCP OAuth and CLI login are separate; a connected plugin does not sign the CLI in. If there is no local shell, installation is unavailable, or the user prefers MCP, continue with the MCP tools and their account-linking flow. Plugin activation alone does not authorize CLI installation or paid generation.

## Unsupported operations and tool scope

AnimaGuru credits cannot be transferred between accounts. For a credit-transfer request, explain this limitation and leave balances unchanged. Do not collect recipient passwords or tokens, use a staff grant, buy credits for someone else, move a project to another workspace, or edit the database to simulate a transfer. Browser access, a shell, or administrative credentials do not turn an unsupported product operation into a supported one.

When the user restricts a request to the AnimaGuru MCP tools, perform it only with those tools. Do not substitute browser automation, the CLI, direct API requests, or another plugin. If the required operation is unavailable, explain the limitation and leave the account unchanged.

Project deletion is not exposed by AnimaGuru MCP. For an MCP-only deletion request, explain that there is no deletion tool. Do not ask for deletion confirmation or attempt deletion through another route. A separate user request to use the studio or CLI follows that workflow's own authorization requirements.

## Find the right project

Use `list_projects` before selecting a project unless the user supplied its ID or a clear project link; pass `query` with the name the user gave to find it, and page with `offset` when `nextOffset` is set. Use `get_project` to inspect characters, animations, credit balance, and generation estimates. Use IDs and character slugs returned by the tools, not guessed names. If the user specifies a team workspace, pass its workspace ID to `list_projects` or `create_project`.

`create_project` makes an empty container. It does not draw or animate anything. After creating it, return the project link and continue with generation only if the user requested artwork.

`move_work` moves characters (with all their animations), saved assets and, to a project in another workspace, the workspace's own avatars to another project the user can write to, for free. Use it to gather work into one project instead of regenerating it. A character with a queued or running job moves after the job finishes.

## Draw and animate

For a requested character, call `get_project` for the current estimate, then `generate_character` with a specific brief and supported style, subject kind, and actions. A drawing job may queue follow-up animation jobs. For a requested animation of an existing drawn character, use its slug from `get_project` and call `animate_character` with supported built-in actions. The server validates action compatibility and available credits.

Generation spends AnimaGuru credits. Follow the user's request and stated budget; show the estimate when it affects the decision. Do not treat installation of this skill as permission to queue paid work. Do not submit the same job again simply because a response is slow or a status check times out.

Tool balances, estimates, credit ranges and queued-job receipts use AnimaGuru credits, including fractional amounts such as 0.7. Compare them directly with the user's credit budget; do not rescale returned amounts or convert credits into currency. Final charges are reported in credits.

## Generate images, video and audio

Use `list_assets` for a project's saved assets, their file SHAs, the sprite art usable as video frames and image references, the configured models, the studio's default model per type (`defaultModels`: the default, then a backup that runs when the request's other settings don't fit it), and each video model's profile (workflows, resolutions, modes and options). Leave `model` out of `generate_asset` unless the user asks for one: staff choose each type's default and can change it at any time, and the dry run's `request.model` names the model chosen. An asset's `options` leave out the name, type, model and prompt shown beside them, and a long prompt rewrite from fal is an excerpt with `expandedPromptLength`; the asset's `url` shows the full text. Call `generate_asset` with `dry_run: true` first to validate the request and get its credit estimate, then again without it to queue the job.

`asset.type` is image, vector, gif, video, music, speech, sfx or model. A `gif` is a looping animation drawn by GPT Image 2.6, for sprite cycles, moving icons and stickers: `frames` 2–16 (default 9), `frameMs` 20–2000 per frame (default 200), `quality`, `aspectRatio` as for images, `transparent`, and up to four `references` to animate, named Image 1… in the prompt; `model` is `fal/gpt-image-2.6-gif` (faster) or `fal/gpt-image-2.6-sunburst-gif` (finer, slower). Its first frame is saved as a PNG still (`preview`), and the GIF's `file` SHA or that still's works wherever a saved image does, so pass it as a video's `reference` to put the GIF in a video. A `vector` is an editable SVG from Ideogram (`fal/ideogram-vector`) or GPT Image 2.6 (`fal/gpt-image-2.6-vector`, from the prompt alone, with `transparent` to leave out the background). An image takes up to four `references`: SHAs of this project's images (uploads included) or sprite art. Generate a character sheet once and reference it in every scene to keep a character consistent; say in the prompt what to take from each, as Image 1, Image 2 and so on. `aspectRatio` is 1:1, 3:2, 2:3, 16:9 or 9:16; use 16:9 or 9:16 for video scenes. `mask` edits only part of Image 1: up to eight rectangles `{x, y, width, height}` in fractions (0–1) of its width and height from the top left. The rest is kept and the result keeps Image 1's shape. Videos refer to saved files by SHA: `reference` (first frame) and `endReference` (last frame) are images or sprite art, `source` is a video asset to extend, and `soundtrack` and `audioReferences` are music, speech or SFX assets. MiniMax H3 Max and H3 Max Turbo offer three workflows:

- `image-to-video`: start from `reference`, end on `endReference`, or both; a `soundtrack` replaces the generated sound for clips of 2 seconds or more.
- `text-to-video`: no image; choose `aspectRatio` (21:9, 16:9, 4:3, 1:1, 3:4 or 9:16).
- `extend-video`: add `seconds` of new footage to `source`, up to 2k, keeping its shape (`aspectRatio: "auto"`) or cropping; `extendOutput: "continuation"` returns only a short overlap and the new footage; up to three `audioReferences`, named in the prompt as Audio 1, Audio 2 and so on.

H3 Max (not Turbo) also offers:

- `reference-to-video`: keep a character or look the same without an exact first frame. Up to nine `references` (images), three `referenceVideos` (2–15 s each, 15 s in all) and three `audioReferences`, twelve files in all, named in the prompt as Image 1, Video 1, Audio 1 and so on. It may open on `reference`, end on `endReference`, and pass `middleReference` at `middleSeconds` (needs both, 480p or 768p).
- `lip-sync`: the face in `reference` says `soundtrack` (speech of 5 s to 15 min); no prompt; `transcribe` helps the mouth; up to 2k.
- `camera-controls`: the camera moves around `reference` along `camera`, 2–12 keyframes `{time, azimuth, elevation, distance}` (time 0–1, angles in degrees); leave out the prompt to keep the scene still.
- `insert-video`: a new scene of `seconds` (5–13) inside `source`, from `insertAt` to `resumeAt` seconds into it, guided by the prompt, `references` and `referenceVideos`; 480p or 768p.
- `recast`: the people in `references` (one photo each, up to four) replace the people in `source` (5–30 s); set `subjectConsent: true` only after the user confirms each person agreed; 768p or 1080p.
- `relight`: relight `source` (up to 15 s) from `lighting`, an image of a sphere lit as wanted; no prompt; up to 2k.
- `3d-to-video`: turn `source`, a 3D render up to 15 s, into realistic footage, following `references` (up to eight) or `generatedReferences` it draws (1–8, default 2); no seed.
- `style`: a preset look (`vhs` with `damage`, `retro-toon-70s`, `low-poly`, `hand-drawn`, `16bit-pixel`) at 768p for 5–15 whole seconds, from text with `aspectRatio` or from `reference`.

FLUX 3 Max (`fal/flux-3-max`) offers `image-to-video` (from `reference`, optionally ending on `endReference`) and `text-to-video` for 5–20 whole seconds at 720p or 1080p. It makes its own sound and takes no `soundtrack`. Its `keyframes-to-video` passes through `keyframes`: 1–10 `{image, seconds}`, each an image or sprite art SHA reached at that second, within the clip's `seconds` and on its own frame of the 24 fps clip; `aspectRatio` is auto (the first keyframe's shape) or a ratio. It always reasons about the prompt: `promptExpansion: "quality"` asks for its thorough level, the others its light one.

HeyGen Video 1 (`heygen/heygen-video-1`) offers `image-to-video` (from `reference` only), `text-to-video` and `reference-to-video` for 5–15 whole seconds at 480p, 768p, 1080p or 2k, with its own sound and no `soundtrack`. From an image or text it runs to 30 seconds with `promptExpansion` balanced or quality, and every second of a clip over 15 seconds costs more. At 1080p and 2k, text-to-video and reference-to-video need `aspectRatio` 16:9 or 9:16. Its `reference-to-video` takes up to nine `references`, three `referenceVideos` (it reads the first 5 s of each) and three `audioReferences`, twelve files in all, named Image 1, Video 1, Audio 1 in the prompt, but no `reference`, `endReference` or `middleReference`; `aspectRatio` auto follows the first image or clip. Images may be up to 5 MB, clips and audio up to 16 MB. Up to 5 s of each reference clip and each reference image after the second add to the cost.

Seedance on BytePlus (`byteplus/seedance-2.5`, `byteplus/seedance-2.0`, `byteplus/seedance-2.0-fast`, `byteplus/seedance-2.0-mini`) offers `image-to-video` (from `reference`, optionally ending on `endReference`; the clip keeps the image's shape), `text-to-video` and `reference-to-video` (up to nine `references` and three `audioReferences`, named Image 1 and Audio 1 in the prompt, without frames or `referenceVideos`; all but 2.5 need an image beside audio) for 4–15 whole seconds (2.5 up to 30) at 480p or 720p (2.0 also 1080p). It makes its own sound and takes no `soundtrack`, `seed` or `promptExpansion`. It refuses images of real people's faces.

Lip-sync, recast, relight and 3d-to-video last as long as their speech or video; the dry run returns the measured `seconds`. References past fal's included allowance add to the cost. H3 takes fractional `seconds` (6.5). `promptExpansion` (disabled, balanced, quality) and `seed` apply to the H3, FLUX and HeyGen Video models. Use only options in the model's profile. The server checks that every file belongs to the project and that credits suffice; relay its message when it refuses. Return the studio link from the result so the user can watch and download the asset.

Jobs are asynchronous. Use `list_jobs` to check status and report the returned job ID, current state, and any failure. If a job is still running, say so instead of claiming the asset is finished.

For visual inspection, use `get_ui_snapshot` for the selected project, character, animation, asset gallery or saved asset. It returns playback timing, frame rectangles, quality findings, credits and pagination; `list_assets` lists the configured models and video profiles, and `estimate_generation` prices a request. Temporary media/download links are private UI metadata; request a fresh snapshot to renew them. Use `get_job` for one job and follow its `pollAfterMs`; stop polling when null. Saved asset and animation outputs are attributed by their exact job ID.

Use read-only `estimate_generation` to validate either a sprite job or asset request before submitting. For sprite generation it returns normalized settings and a credit range. When submitting a user-requested job, supply a fresh UUID in `request_id` and retain it for retries of that same submission. Reusing it with different settings is rejected. A replay returns the original job; do not create a new ID merely because a response timed out.

Submit a reviewed sprite request through its dedicated tool: `generate_character` for drawing, `animate_character` for built-in actions, `redraw_character` for revising artwork with a change brief, or `generate_custom_animation` for motion from a prompt and frame descriptions. Pass the normalized estimate's fields directly, without its `kind` field or a `job` wrapper; drawing maps `subjectKind` to `subject_kind`. Keep its selected models and the same `request_id` for transport retries. Redraws and custom animation also support `dry_run` for validation without generation. These operations regenerate complete artwork or animations; selecting a frame for feedback does not make them in-place frame editors.

## HeyGen avatars

`list_avatars` browses HeyGen's public avatar characters (groups) from any accessible project, or, with `ownership: "private"`, the avatars of the project's workspace. `list_avatar_looks` with `group_id` lists a character's looks (outfits, poses, styles); without it, HeyGen's public looks, filterable by `avatar_type`. A look's id is what HeyGen renders with; its `supportedEngines` name the engines that render it. A private avatar belongs to the workspace whose project created it: every project in that workspace can use it, no other workspace can see, change or render it, and public avatars are read-only. The voice HeyGen clones for a digital twin belongs to its workspace the same way.

`create_avatar` makes an avatar and is charged when HeyGen accepts it. Call it with `dry_run: true` first for the estimate. `avatar.type` is:

- `prompt`: a synthetic character from a description of up to 1000 characters (name age, expression, wardrobe, setting and light), with optional `aspectRatio` and up to three `referenceImages` for wardrobe or style. Add `lookId`, one of the workspace's looks, to put that same character in a new outfit or setting.
- `photo`: one clear, front-facing portrait.
- `digital_twin`: footage of a real person (about two minutes of natural talking), which also clones their voice for this workspace alone.

Files are `{"type": "file", "sha": …}` for the project's images or sprite art (photos and references) or video assets (footage) from `list_assets`, or `{"type": "url", "url": …}` for a public HTTPS file. Photos and footage show a real person. Set `subjectConsent: true` only after the user confirms that this person agreed to become an avatar; never assume it, and do not make avatars of people the user has no permission to depict. A digital twin renders only after its subject records consent: call `request_avatar_consent`, give the returned 24-hour link to that person rather than opening it yourself, and check `consentStatus` with `get_avatar`.

New looks start `processing`. Poll `get_avatar` with `look_id` about every 20 seconds until `completed` or `failed`, and report `error.message` when one fails. Do not create the avatar again because it is still processing; reuse the same `request_id` only to retry a request whose response was lost.

`create_avatar_looks` applies a Look Pack (`method: "look_pack"`, five looks) or a single template (`method: "template"`, two looks) to one of the workspace's looks; `list_avatar_templates` lists the template ids in female and male variants, so choose the one matching the avatar. `update_avatar` sets an avatar's default voice (`group_id` with `default_voice_id`, a public voice or one of the workspace's cloned voices) or renames a look (`look_id` with `name`). MCP does not delete avatars; when the user asks to delete one, point them to `animaguru avatars delete` in the CLI.

`create_avatar_video` films one completed look, the workspace's or a public one, and saves the clip to the project as a video asset. Give `video.script` (up to 1,500 characters) for the avatar to speak, or `video.soundtrack`, the file SHA of saved speech or music from `list_assets`, for it to lip-sync (up to 120 seconds). A script speaks in the look's own voice unless `video.voiceId` picks another: `list_avatar_voices` lists public voices by `language` and `gender`, and with `ownership: "private"` the voices cloned from the workspace's digital twins; another workspace's cloned voice is refused. `video.model` is the engine (`heygen/avatar-iv` by default, `heygen/avatar-v`, `heygen/avatar-iii`) and must be one the look's `supportedEngines` list. A digital twin films only once its subject's consent is accepted. Call it with `dry_run: true` first: the server checks the look, voice and audio and returns the estimate. The video is charged for the seconds HeyGen makes; poll `get_job` with the returned id, and reuse `request_id` only to retry a lost response.

## Motion library

When writing PixiJS motion for an AnimaGuru video film, first call `search_motion_examples` with a natural-language description and/or keywords (optional `category`, such as `kinetic-typography` or `application-ui`, and `labels`, such as `mobile` or `vertical`); `list_motion_categories` lists every category. `get_motion_example` returns the example's beats, options, usage and `files` (the scene and its shared modules, relative to `src/scenes/`). Write all files, call the entry function from `Film.build()`, and adapt copy, colors and timing to the brief. In a workspace animation, kit imports move three folders deeper (`"../kit"` → `"../../../../runtime/kit"`). These tools are read-only and free.

## Asset library

Every plan (Individual Starter, Individual Pro and its trial, Team) and members of a team on the Team plan can use AnimaGuru's asset library of ready-made sprites (with animation sheets and frame data), images, video clips, music, voice-over speech and sound effects. Before generating a common asset (a whoosh, background music, a stock clip, a pixel character), call `search_asset_library` with a description and/or keywords (optional `type` and `labels`); a query-less call browses the newest entries. `get_library_asset` returns its details and 15-minute download links. `import_library_asset` copies it into a project at no credit cost: media become saved assets whose `file` SHA works as a video reference, end frame or soundtrack in `generate_asset`, and sprites become characters with their animations. For accounts without a plan, the tools explain that a plan is needed; say so rather than retrying.

## Brand kits

Use `list_brands` with the personal or chosen team workspace, then `get_brand` for the full identity and guide. `create_brand` takes `brand: {name, ...knownFields}` and starts omitted colors/fonts neutral. To research an official website supplied by the user, use `research_brand` and poll that same brand with `get_brand` until `ready` or `failed`. Keep `request_id` for retries of a creation.

`upload_brand_image` takes `brand_id` and `image: {name, kind, url}` for a public HTTPS image up to 32 MiB, or `{name, kind, data, mimeType}` for standard base64 up to 8 MiB. `kind` is `logo` or `image`. Assign the returned file ID using `update_brand` with `patch: {logo: FILE_ID}` or `patch: {assets: [FILE_ID, ...]}`; the assets list replaces the previous list, so preserve existing IDs when adding one. Uploaded files must belong to that brand. `download_brand` returns `textFiles` and temporary media links with workspace-relative `branding/` paths; save the text and fetch the media into those paths. With `file_id` it returns only one file's link. Download links last 15 minutes and recheck workspace access; call again to refresh. Full-kit downloads and edits wait for research to finish.

## Video posters

`set_video_poster` replaces the poster (cover image) of a video the user uploaded to AnimaGuru's video library. `video_id` is the `vid_…` ID from the submit result or the video's watch URL (`/videos/VIDEO_ID`). `image` is `{type: 'file', project_id, sha}` for a saved image from `list_assets`, such as key art generated with `generate_asset`; `{type: 'url', url}` for a public HTTPS PNG, JPEG or WebP up to 32 MiB; or `{type: 'base64', mediaType, data}` up to 8 MiB. An image over 2 MiB is saved as a 1280-pixel JPEG. A public video's new poster goes back to staff review and the video is hidden from the public until it is approved, so tell the user before replacing a public video's poster. It spends no credits.

## Gallery folders

`list_gallery` shows a workspace's video gallery (personal by default, or `workspace` for a team): its folders, each with `items`, `people` (how many accounts it is shared with) and `link` (whether anyone with its unlisted link can watch what is in it), then a page of its items: its projects' animations, each with `videoCount` and `latestVideo` (its newest video), and its uploaded videos, each with `folderId` and its `item` key. `folder_id` narrows it to one folder, or `"none"` to items in no folder; `query` searches animation and project names, video titles and descriptions across the whole gallery; `sort` is `recent` (default), `oldest` or `name`. It returns up to `limit` items (50 by default) with `total`; while `nextCursor` is not null, call it again with `cursor` and the same other choices. In a large gallery, search for what the user names rather than reading every page. `create_gallery_folder` adds a folder (names are unique in a workspace, ignoring case) and `rename_gallery_folder` renames one; reuse an existing folder rather than creating a second with the same name. `move_gallery_items` files items in a folder, or takes them out of every folder with `folder_id: null`; it takes `item` keys, a `vid_…` ID or `PROJECT_ID/NAME`. A video made from an animation shows under it, so move the animation. Whoever a folder is shared with can watch what is filed in it: before moving items into or out of a folder whose `people` or `link` show it is shared, tell the user who gains or loses access, and move only what the user names. Deleting a folder and sharing one are done in the studio's Gallery, or with `animaguru gallery folders delete` in the CLI. To upload a finished film straight into a folder, the user runs `animaguru submit --folder FOLDER --yes`.

## Other operations

The MCP tools cover project inspection, project creation, brand kits, video posters, gallery folders, motion library search, asset library search and import, character drawing/redraws, built-in and custom animation, asset generation, HeyGen avatars, previews, and job status. For reference imports, project ZIP exports, or project deletion, direct the user to the AnimaGuru studio at the project's returned URL or to the locally installed AnimaGuru CLI when available. Private UI media links can download existing saved media. Do not claim unsupported operations were performed through this plugin.
